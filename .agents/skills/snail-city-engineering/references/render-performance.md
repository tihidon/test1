# Render and performance
Read [SC-REND-01](standards/standardi/SC-REND-01-CIST-KOD-I-RENDER.md), [PL-01/CSS-01](standards/standardi/SC-PL-01-LAYOUT-INVALIDATION-REVIEW-STANDARD.md), [SC-LOOP-01](standards/standardi/SC-LOOP-01-LOOP-I-BUG-AUDIT.md). One game scheduler; dirty idle rendering; bounded active steps. Derived cache owner, key, invalidation, bound, lifecycle. Avoid blocking queries/geometry reads or redundant upload in hot paths. Preserve needed canvas resize/invalidation. Restore WebGL state/resources; dispose callbacks and observers. Audit loop exit/progress, microtask starvation, retries, reentry and lifecycle. Use actual trace and external watchdog, not a second game loop. Controlled A/B/R identical scene/save/cache/device/viewport; 20–30 repeats when required. Record p50/p95/max, long tasks and frame time. JS submission isn't presentation, local gesture isn't field INP. Historical [shop](performance-evidence/SC-P1-shop.md) and [startup](performance-evidence/SC-P1-startup.md) reports are 0.8.90 evidence, not current performance proof.
