## Run a regression investigation
1. Pin the target commit, publish root, HTML and worker hashes. Read the actual control, handler and save schema. Freeze the expected visible change and failure reason before touching code.
2. Use the repository's isolated Python environment and tools/qa/runtime_watchdog.py --out NEW_DIRECTORY --scenario REVIEWED_JSON. A scenario must use selectors verified on that build. Confirm every intended assertion executed. Inspect partial output and watchdog status on timeout.
3. Record startup, idle, interaction, save, reload, offline and return-to-map as distinct phases. Start with only the probes that can distinguish the competing explanations.
4. For city → race → city → tap, record input dispatch, actual handler, asynchronous work, state mutation and first visible response. Repeat the same map tap without entering the race. For shop first-open, compare first and warm opens with the same inventory. Keep assets, state and viewport matched.
5. For a duplicate RAF hypothesis track owner, pending handle, cancellation, reentry and rescheduling. Contrast two concurrent chains for one owner with one healthy chain running across many frames. Check listener removal, once/abort behavior, intervals and observers after repeated exits. Compare live counts after warm-up.
6. For stale async writes, record request identity, save revision and completion order. Control delays only in an isolated fixture. Compare reversed completion order to the serialized control. Require the persisted revision and visible state to agree.
7. For a GPU hypothesis correlate source content revision, texture handle, dimensions and context generation. Compare repeated upload of unchanged pixels with legitimate reupload after context restoration. In a heap investigation check retained owners after repeated teardown, alongside resource create/delete counts. A single rising sample warrants investigation.
8. For a layout hypothesis capture the write and dependent geometry read in the same task and inspect forced layout events. Compare batched reads/writes. For a timing claim repeat separately without tracing, precise coverage or stack wrappers using PL-01. Record all raw runs including failures.
9. For PW-01 prepare a sanitized persistent profile, establish worker control, perform a player action and verify committed save revision. Close the browser, disable network, reopen the same profile and origin and compare identity, level, inventory, visible art and worker response. Run cache upgrade, missing response and recovery on disposable profiles. Report desktop and physical Android separately.
10. Reduce a failing sequence while preserving the failure reason. Use bisect only with a stable automated reproducer. Validate the frozen assertion on baseline and candidate plus an unaffected control. Hand original artifacts to an independent reviewer.
